# Kitchen Monitor UIモック 機能仕様

- 文書版: 0.3
- 現行確認日: 2026-07-22
- 対象: `kitchen-monitor-ui-prototypes` の現行フロントモック
- 想定端末: iPad横画面を中心としたブラウザ

## この文書の役割

この文書は、UIモックで確認できる画面・操作・表示の変化を、営業や業務担当者も確認できる言葉で記録する。

- モックの見た目が変わったら、該当する画面・操作・未決事項を同じ変更で更新する。
- 本番仕様として未確定の内容は、`要確認`として扱う。モックで操作できても、業務ルールが決まったことにはならない。
- コード名、数値、内部構成は主文で扱わない。必要な場合だけ末尾の「実装メモ」を参照する。

### ステータス

| 表記 | 意味 |
| --- | --- |
| 現行 | 現在のモックで確認・操作できる |
| 簡易 | UI確認用の動き。保存や外部連携はない |
| 比較用 | レイアウトを比較するための案。本番機能とは限らない |
| 要確認 | 業務・運用・実装方針を決める必要がある |

## 1. モックで確認する利用シーン

キッチンまたはデシャップ担当者が、注文の優先度と調理状況を見ながら、調理済み数や完了を更新する場面を確認する。

| 利用シーン | モックで確認すること |
| --- | --- |
| 注文を優先順に処理する | 経過時間、注意が必要な注文、商品詳細を素早く確認できるか |
| 同じ卓の進み具合を把握する | 複数注文をテーブル単位でまとめて見られるか |
| 商品の調理状況を更新する | 数量変更、完了、取り消しが誤操作なく行えるか |
| 表示を自分の担当に合わせる | 部門、テーブルグループ、並び順を切り替えられるか |

## 2. 画面の全体像

| 画面 | 目的 | 現行の基本候補 | 比較用 |
| --- | --- | --- | --- |
| 注文別 | 1注文ごとに商品と調理状況を処理する | N型・横スクロール | N型・ページ、Z型・縦展開 |
| テーブル別 | 同じテーブルの複数注文をまとめて確認する | N型・横スクロール | N型・ページ |
| 設定 | 表示単位・部門・テーブルの見せ方を切り替える | モーダル | — |

N型は、カードを上から下へ並べ、列が埋まると右の列へ続ける表示である。横スクロールでは、画面に収まらない列を横方向に連続して確認する。

> 比較用のレイアウトは、見せ方を決めるためだけの入口である。利用者向けの設定として残すかは、別途決定する。

## 3. 共通の見せ方と操作

### 3.1 表示単位の切替

- ヘッダーから`注文`と`テーブル`を切り替える。
- 選択すると、それぞれの基本候補の画面を開く。
- URLを共有または再読み込みしても、同じ画面を開ける。

### 3.2 時間の見せ方

| 状態 | 現行の表示 | 要確認事項 |
| --- | --- | --- |
| 通常 | 経過時間を表示する | 目標時間をどこで設定するか |
| 期限間近 | オレンジで`あとN分`を表示する | 現行は残り3分以内 |
| 超過 | 赤で`N分超過`を表示する | 現行は注文から15分以上 |

- 注文別では注文カード、テーブル別では各注文と超過件数に時間状態を反映する。
- 商品ごとの目標時間がある場合は、詳細内で注文経過時間との差分を参考表示する。

### 3.3 一覧の移動と通知

- 横スワイプ、左右ボタン、下部の進捗表示で列を移動できる。
- カードや商品が消えた後も、可能な範囲で見ていた横位置を保つ。
- 数量変更、完了、取消の結果は画面下部のトーストで短時間知らせる。
- 音量アイコンはON/OFFを切り替えられるが、現行モックでは音を再生しない。

## 4. 注文別画面

### 4.1 一覧と注文カード

- 経過時間が長い注文から先に表示する。カードの高さが異なっても、列内の空きが大きくならないように並べる。
- 長い注文は商品行の途中で切らず、右の列へ続けて表示する。続き側に注文ヘッダーは繰り返さない。
- 注文カードには、テーブル番号、経過時間、人数、時間状態、注文メモの要約を表示する。
- 商品行には、調理済み数、商品名、コース、オプション、商品メモ、同一商品の未調理合計を表示する。

### 4.2 商品行の操作

| 操作する場所 | できること |
| --- | --- |
| 左の数量 | 調理済み数を変更する |
| 中央の商品情報 | オプション・メモ・時間情報を詳しく見る |
| 右の合計数 | 同じ商品の未調理数と注文内訳を見る |

- 商品詳細では、全文のオプション・メモ・注文情報を確認でき、数量も変更できる。
- 同一商品の集計は、同じコース・同じメニューを別の商品として扱う現行案である。
- 注文別では、商品を全数調理済みにしても、その商品行はすぐには消えない。

### 4.3 注文全体の完了

| 現在の状態 | 操作 | 次の状態 |
| --- | --- | --- |
| 表示中 | `すべて完了` | 完了猶予中。取り消せる |
| 完了猶予中 | `完了取消` | 通常表示へ戻る |
| 完了猶予中 | 取り消さずに時間経過 | 注文カードを一覧から非表示にする |

現行の取消猶予は3秒である。時間、対象範囲、復元方法は本番化前に決める。

### 4.4 部門による絞り込み

- 設定で選んだ部門に対応する商品だけを表示する。
- 表示対象の商品がない注文は、注文カードごと表示しない。
- ヘッダーには選択している部門数を表示する。

## 5. テーブル別画面

### 5.1 テーブルカード

- 同じテーブルの複数注文を、1つのテーブルカードへまとめる。
- カードには、テーブル番号、最も古い注文の経過時間、注文件数、人数、時間状態を表示する。
- カード内では注文ごとに区切り、各注文の経過時間、商品数、メモの有無を確認できる。
- 長いテーブルカードは、注文または商品行の区切りで右の列へ続ける。集計は最後のカードだけに表示する。

### 5.2 商品完了後の扱い

| 現在の状態 | 操作 | 次の状態 |
| --- | --- | --- |
| 未調理・一部調理済み | 全数を調理済みにする | 非表示猶予中。取り消せる |
| 非表示猶予中 | 取消または数量を減らす | 商品行を残す |
| 非表示猶予中 | 取り消さずに時間経過 | 商品行を非表示にする |

- 現行の取消猶予は5秒である。
- 表示対象の商品がなくなると、テーブルカードも一覧から非表示にする。

### 5.3 テーブルの整理

| 機能 | 現行の動き | 要確認事項 |
| --- | --- | --- |
| ピン留め | 優先して見たいテーブルを先頭側に固定する | 保存単位、解除条件、上限 |
| 並び順 | 最古注文順、卓番号順、最終追加順、手動順を選ぶ | 店舗・端末ごとの初期値 |
| 手動移動 | 編集モードで前後へ1件ずつ動かす | ドラッグ操作、保存、他端末同期 |
| グループ化 | ホール・個室・カウンターなどの連続した列で表示する | グループの定義と初期ON/OFF |

- ピン留めは選んだ並び順より優先する。
- グループ化中は、グループの中で並び替える。現行の手動移動では別グループへ移動できない。
- グループ名を選ぶと、そのグループの先頭へ移動する。横スワイプでも選択中のグループ表示が追従する。

## 6. 設定

| 設定 | できること | 保存の扱い |
| --- | --- | --- |
| 表示単位 | 注文別・テーブル別を切り替える | 現行は画面内のみ |
| 比較用レイアウト | 検討中のレイアウトを開く | 本番設定に残す前提ではない |
| 表示部門 | 検索、全選択、全解除、個別選択 | 現行は同じモック内で共有し、再読み込みで初期化 |
| テーブルグループ化 | テーブル別をグループごとに囲って表示する | 現行は横スクロール画面にだけ反映 |

- 設定は、背景タップ・閉じる・キャンセルでは反映しない。`この内容で保存`で反映する。
- 設定の保存単位（店舗、端末、ユーザー）は要確認である。

## 7. モックの範囲外

次は現在のUIモックでは確認できない。本番仕様として扱わない。

- API通信、認証、権限、WebSocketによるリアルタイム更新
- 操作内容のサーバー保存、他端末との同期、競合解決、再送
- 通信遅延、オフライン、再接続、エラー表示
- 営業日切替、注文取消、返品、品切れとの連携
- 実際のテーブルグループ、部門マスタ、商品マスタとの接続
- 注文別とテーブル別をまたぐ調理状態の同期

## 8. 決めること

| ID | 論点 | 現行案 | 決めること | 優先度 |
| --- | --- | --- | --- | --- |
| D-01 | 基本表示単位 | 注文別・テーブル別を切替 | 店舗・端末ごとの初期表示と利用可否 | 高 |
| D-02 | 注文別レイアウト | N型・横スクロール | 比較案を廃止するか | 高 |
| D-03 | テーブル別レイアウト | N型・横スクロール | ページ案を廃止するか | 高 |
| D-04 | 目標時間 | 全注文15分 | 店舗・部門・商品ごとのどれで管理するか | 高 |
| D-05 | 期限到達時 | `0分超過` | 期限到達と超過のどちらとして扱うか | 中 |
| D-06 | 商品目標時間 | 注文経過時間との差分 | 起点、停止条件、表示対象 | 高 |
| D-07 | 完了の粒度 | 注文別は注文、テーブル別は商品 | 商品・注文・テーブルの消去条件 | 高 |
| D-08 | 取消猶予 | 注文3秒、商品5秒 | 秒数、操作範囲、復元方法 | 高 |
| D-09 | 同一商品集計 | コースIDとメニューIDで集計 | 部門フィルタ外を合計に含めるか | 高 |
| D-10 | 商品詳細 | ポップオーバー | 常時表示、モーダル、ドロワーのどれにするか | 中 |
| D-11 | テーブルグループ | カテゴリ別の連続表示 | グループ定義と初期ON/OFF | 高 |
| D-12 | ピン・手動順 | 端末内の一時状態 | 保存、上限、他端末同期 | 中 |
| D-13 | 表示部門 | 複数選択 | マスタ対応と0件選択可否 | 高 |
| D-14 | 注文メモ | 一覧の要約と詳細全文 | 強調度、表示順、既読状態 | 高 |
| D-15 | 通知音・スヌーズ | 音のON/OFF表示のみ | 発火条件、解除方法、端末制約 | 中 |
| D-16 | 設定の保存 | ほぼ未実装 | 店舗・端末・ユーザーの保存単位 | 高 |

決定は、レイアウト → 完了の扱い → 時間ルール → 表示・設定の保存単位、の順で進める。

### 現行実装の前提

- Vue Composition APIと固定モックデータで構成し、API・Pinia・Vue Routerは使用していない。
- 注文別とテーブル別は同じ初期データを使うが、調理操作の状態は同期しない。
- 音量のON/OFFだけはブラウザに保存し、それ以外の操作状態は再読み込みで初期化する。
- レスポンシブ表示は、コンテンツ領域を計測して1〜3列を決める。現行の最小列幅は`290px`、列間は`14px`である。
- 主な実装の入口は `src/App.vue`、各 `*Workspace.vue`、`useOrderViewMock.js`、`useResponsiveColumnLayout.js`、`useTableLayoutPreferences.js` である。
