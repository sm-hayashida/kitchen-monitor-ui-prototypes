## 0. この文書の役割と更新契約

この文書を、現行モックの画面、デザイン、操作、比較項目、設定、固定データ、状態管理、回帰確認の正本とする。新しいチャットや作業者は、モックを変更する前にこの文書とリポジトリ直下の`AGENTS.md`を読む。

### 0.1 必須の更新ルール

- 画面、表示内容、配色、操作、設定、固定データ、URL、状態保持、主要コンポーネントを変更した場合は、この文書を同じ作業単位で更新する。
- 文書版、現行確認日、該当節、回帰チェック、末尾の変更履歴を更新する。
- 「コードだけ変更」「文書だけ後追い」を完了状態としない。
- 文書とコードが食い違う場合、現在のコードを観測事実として確認し、同じ作業内で文書を一致させる。食い違いを根拠に仕様を推測しない。
- 本番仕様として未決定の内容は、モックで動いていても`比較用`または`要確認`として残す。
- push、GitHub Pages公開、MR、外部共有は文書更新に含まれない。ユーザーの明示依頼がある場合だけ行う。
- 冒頭の公開スナップショットは、GitHub Pagesのデプロイ成功と公開ページ確認後だけ更新する。ローカルモックが公開版より新しい期間は、古い公開コミットを正直に残す。

## 2. モックの目的と非対象

キッチンまたはデシャップ担当者が、注文の優先度、同じ卓の進み具合、商品ごとの調理状況を確認し、表示単位と操作方式を比較するためのフロントモックである。

### 2.1 主な確認対象

| 利用シーン | 確認すること |
| --- | --- |
| 注文を優先順に処理 | 経過時間、期限間近、超過、メモ、商品情報を素早く読めるか |
| 同じ卓をまとめて処理 | 複数注文をテーブル単位で把握できるか |
| 調理状況を更新 | 数量変更、行完了、注文完了、取消が誤操作なく行えるか |
| 調理済み履歴を確認 | 商品・注文・テーブル単位で検索、ソート、未調理への復元ができるか |
| 表示を担当へ合わせる | 部門、テーブルグループ、列数、表示情報を切り替えられるか |
| UI案を比較 | レイアウト、密度、数量、操作、時間、配色、固定データを共有URLで比較できるか |

### 2.2 非対象

- API通信、認証、権限、サーバー保存
- WebSocketなどのリアルタイム受信、他端末同期、競合解決
- 通信遅延、オフライン、再接続、エラー処理
- 本番の営業日、注文取消、返品、品切れ、プリンター連携
- 実際の部門・Waiterカテゴリ・テーブル・商品マスタ接続
- 実音の通知、OS通知、バックグラウンド動作
- 注文別、テーブル別、リスト型、調理済み画面をまたぐ調理状態の同期

## 3. URLと画面構成

### 3.1 有効なURLハッシュ

| URLハッシュ | ヘッダータブ | 用途 | 区分 |
| --- | --- | --- | --- |
| `#order-n-scroll` | 注文 | 注文別・N型・横スクロール | 現行の基本候補・既定 |
| `#order-n-page` | 注文 | 注文別・N型・ページ | 比較用 |
| `#order` | 注文 | 注文別・Z型・縦展開 | 比較用 |
| `#table-n-scroll` | テーブル | テーブル別・N型・横スクロール | 現行の基本候補 |
| `#table-n-page` | テーブル | テーブル別・N型・ページ | 比較用 |
| `#list` | リスト型 | 稼働中画面を移植した7列一覧 | 後方互換 |
| `#completed` | 調理済み | 新UI向け調理済み履歴 | 現行モック |

- 未指定URL、未知のURL、廃止済みの旧URLは`#order-n-scroll`へフォールバックする。
- 商品単位の「調理中一覧」画面は有効ルートに含めない。旧ソースが残っていても`src/App.vue`から参照しない。
- 調理済み画面内の`商品単位`は履歴の括り方であり、廃止した調理中の商品単位画面とは別物である。
- 画面と比較設定はハッシュとクエリへ反映され、再読み込み・共有URLで復元できる。

### 3.2 共通ヘッダー

- 左側に`注文`、`テーブル`、`リスト型`、`調理済み`の4タブを、1つの連続したトグルグループで表示する。
- 選択中タブは白背景で表示する。どの画面からでも4画面の基本候補へ移動できる。
- 右側の音量ボタンでマスター通知音の表示状態を切り替える。実音は鳴らない。
- 設定入口は右端の歯車1個だけとし、同じ役割のアイコンを重複させない。
- 注文・テーブルの横スクロール位置、ページ範囲、グループ、並び順など、画面固有の補助操作はヘッダー右側へ表示する。

## 4. 共通デザイン基準

### 4.1 画面フレーム

- 基準モニターフレームは最大`1194px × 834px`、ヘッダーは`60px`。
- フレームはブラウザ中央へ配置し、背景は薄いグレー、作業領域はスレート系の薄いグレーとする。
- iPad横画面を主対象とし、`1194 × 834`と`1024 × 768`で主要操作が横にはみ出さないことを回帰確認する。
- 大きなデスクトップ幅でも、右下の`比較ラボ`ボタンはモニターフレーム内に残す。

### 4.2 現行の基本配色

| 用途 | 基本値・見え方 |
| --- | --- |
| ヘッダー・主要操作 | オレンジ `#ff7a13` / `#f97316` |
| 作業領域 | スレート系 `#eef1f5` |
| 通常カード | 白、薄いスレート境界、控えめな影 |
| 通常カード見出し | `#f8fafc` |
| 期限間近 | オレンジ系面・境界・`あとN分` |
| 超過 | 赤系面・境界・`N分超過` |
| 完了 | 緑系の状態表示 |
| メモ | 淡い黄・橙系で本文と区別 |
| 補助情報 | スレート、リンク・コースは必要に応じ青系 |

- 色だけに依存せず、期限間近・超過・完了・選択中は文言、境界、アイコンでも区別する。
- 警告・超過カードは、比較テーマを変えても業務状態としての優先度を失わない。
- ピン留めはオレンジの境界・左インセット等で示す。

### 4.3 調理済み画面パレット案

比較テーマ`調理済み画面（橙＋スレート）`を選ぶと、調理済み画面で採用した次の配色を注文・テーブルカードへ適用する。

- オレンジのヘッダーとアクセント
- 白いカード、`#d6dde6`の境界、控えめな影
- 通常カード見出しを淡い橙`#fff7ed`
- 罫線と作業面をスレート系で統一
- 期限間近、超過、ピン、取消猶予の状態色は優先して維持

これは比較用であり、既定テーマは`現行オレンジ`のままとする。

### 4.4 テーブル番号

- `T43`など3文字まで、通常の文字サイズを維持する。
- 4文字以上も省略せず表示し、文字数に応じて縮小する。
- 縮小の下限は`6px`。6文字以上では字間も詰める。
- 注文カード、テーブルカード、同一商品モーダルで同じ縮小規則を使う。

## 5. 共通レイアウトと移動

### 5.1 カード列数

- `自動`、`2列`、`3列`、`4列`を選べる。`1列`は選択肢に含めない。
- 自動では利用可能幅、最小カード幅、`14px`の列間から2〜4列を算出する。
- 現行基準の最小カード幅は`290px`。比較では`260 / 290 / 320 / 360px`を選べる。
- 列数を明示した場合は自動算出より指定を優先する。
- 4列時も、テーブル番号、経過時間、注文件数、人数、状態をカードヘッダー内の1行に収める。
- 列数は注文・テーブル、横スクロール・ページで共有する。URLへ反映されるが、モジュール内設定自体は再読み込みで初期化される。

### 5.2 N型カード分割

- カードは利用可能な列高へ収まる位置で分割する。
- 商品行の途中では分割しない。注文カードは商品行、テーブルカードは注文区切りまたは商品行の境界で分割する。
- 続きカードでは同じ主ヘッダーを繰り返さない。
- カード高は内容量に合わせる。注文順を大きく崩さず、列内の空きを抑える。

### 5.3 横スクロール

- 横スワイプ、1列単位の左右ボタンで移動する。
- ヘッダー内に`先頭表示列–末尾表示列 / 総列数`と進捗レールを表示する。
- 横スクロール領域は列幅＋`14px`を1ステップとして扱う。
- データや列数が変わった場合、可能な範囲で直前の横位置を維持する。
- テーブルのグループ表示では、可視列に合わせて選択中グループを追従させる。

## 6. 注文別画面

### 6.1 レイアウト案

| レイアウト | 特徴 |
| --- | --- |
| N型・横スクロール | 基本候補。列を上から下へ埋め、右へ連続して移動 |
| N型・ページ | 画面高に収まる列単位でページ送り |
| Z型・縦展開 | 比較用。縦方向へ展開する従来案 |

### 6.2 注文カード

- 基本順は経過時間が長い注文を先にする。ピン留め注文はその順より優先する。
- ヘッダーにテーブル番号、人数、テーブルカテゴリ、時間表示、ピンを1行で表示する。
- 時間表示は`経過時間`と`残り時間（超過後は超過時間）`を設定と比較ラボから切り替えられる。既定は`経過時間`。
- `経過時間`では常に`N分経過`、`残り時間`では目標到達前に`あとN分`、到達後に`N分超過`を表示する。同じカードへ経過時間と残り・超過時間を同時表示しない。
- 期限間近と超過は、時間文言に加えて既存のカード背景、境界、状態色でも区別する。視覚表示を短縮しても読み上げ用ラベルには経過時間と目標との差を保持する。
- 注文メモは詳細画面へ隠さずカード内に全文表示する。
- 商品行は表示名、コース、全トッピング、商品メモを表示する。省略チップや詳細ポップオーバーを基本動作にしない。
- 表示名は`kitchen_print_name`があれば優先し、なければ商品名を使う。
- カード末尾に`すべて完了`を表示する。比較で非表示にできる。

### 6.3 数量表示の現行基準

- 既定は`N 左残数／合計（現行）`。
- 左の主数値は、その注文商品の未調理残数。
- `/合計`は、全注文にある同一商品の未調理合計。
- 同一商品キーは`コースID（なければuncoursed）＋メニューID`。同じメニューでも別コースは別集計とする。
- 部門絞り込み外の商品を集計へ含めるかは本番要確認。

### 6.4 数量変更

| 数量操作モード | 動作 |
| --- | --- |
| その場で数量変更（既定） | 数量を押すと商品行内の選択UIを開く |
| 同一商品一覧で数量変更 | 数量を押すと同一商品内訳モーダルを開き、注文ごとに変更する |

- 商品数量が6個以下の場合、`0`から合計数までを直接選ぶ。
- 7個以上の場合、`−`、`＋`、`全て`で変更する。
- その場変更のUIからも`同一商品の内訳を見る`へ移動できる。
- 内訳モーダルは1ページ8注文。左右キー、横スワイプ、最初・前・次・最後のボタンでページ移動する。
- モーダルを開いた元の注文を`表示元`バッジ、専用背景、aria-labelで強調し、その注文を含むページを最初に開く。
- モーダルにはテーブル、経過時間、期限状態、人数、残数、調理済み数、トッピング、商品メモを表示する。

### 6.5 商品行タップ

| 比較モード | 動作 |
| --- | --- |
| 残り全部を完了（既定） | 数量領域以外の商品行を押すと残数をすべて調理済みにする |
| 安全タップ | 残り1個は即完了、残り2個以上は数量確認を開く |

- 完了すると商品行全体に取消プログレスを表示する。
- 猶予中に同じ行を再タップすると、完了前の数量へ戻す。
- 注文別では既定5秒の猶予後も行を消さず、全数調理済みの表示で残す。
- 数量操作領域のタップは行完了を発火しない。

### 6.6 注文全体の完了

| 状態 | 操作 | 結果 |
| --- | --- | --- |
| 通常 | `すべて完了` | 注文完了の取消猶予を開始 |
| 猶予中 | `完了取消` | 通常状態へ戻す |
| 猶予中 | 既定3秒経過 | 注文カードを一覧から非表示 |

- 比較では注文の猶予を`即時 / 2 / 3 / 5秒`へ変更できる。
- 注文カードを分割している場合、元注文に属する全セグメントを同じ完了状態として扱う。

### 6.7 注文のピン留め

- カード右上のピンで注文を先頭側へ移動する。
- 分割された同じ注文の全セグメントへピン状態を反映する。
- レイアウトを切り替えてもSPA内では維持する。再読み込みでは初期化する。

## 7. テーブル別画面

### 7.1 テーブル集約

- 同じテーブルの複数注文を1テーブルカードへ集約する。
- ヘッダーにテーブル番号、最古注文の経過分、注文件数、人数、期限状態、ピンを表示する。
- カード内を注文ごとに区切り、注文番号、注文経過、商品数、注文メモを表示する。
- カード末尾に`総点数中 / 未調理点数`を表示する。

### 7.2 商品行の完了と非表示

| 状態 | 操作 | 結果 |
| --- | --- | --- |
| 未調理・一部調理済み | 商品行タップ | 全数調理済みにし、非表示猶予を開始 |
| 猶予中 | 同じ商品行を再タップ | 完了前の数量へ戻す |
| 猶予中 | 既定5秒経過 | 商品行をテーブルカードから非表示 |

- 全商品が非表示になると、該当テーブルカードも一覧から消える。
- 数量変更と同一商品内訳は注文別と同じUIを使う。
- 手動並び替えモード中は商品操作を無効化する。

### 7.3 テーブルの整理

| 機能 | 現行の動き |
| --- | --- |
| ピン留め | ピン留めテーブルを先頭側へ優先。初期固定データでは`T2`をピン留め |
| 並び順 | 最古注文順、テーブル番号順、最終追加順、手動順 |
| 手動並び替え | 編集モードで左右1件ずつ移動 |
| グループ化 | Waiterカテゴリ相当のホール・個室・カウンター等を連続列で表示 |
| グループ移動 | ヘッダーのグループ選択から先頭列へ移動 |

- ピン留めは選択中の並び順より優先する。
- グループ化中はグループ内で並び替え、手動移動で別グループへ越境しない。
- グループごとに背景トーン、卓数、期限間近件数、超過件数を表示する。
- N型・ページではグループ横スクロールを使用しない。

## 8. 後方互換のリスト型

### 8.1 見た目の保護範囲

- 稼働中Kitchen Monitorのリスト画面を、共通ヘッダー以外は再デザインせず固定データへ移植する。
- フォント、罫線、余白、状態ボタン、行色、右下の`手動追加`を後方互換の回帰対象とする。
- 新UIカードのデザインをリスト本体へ波及させない。

### 8.2 7列一覧

| 列 | 内容 |
| --- | --- |
| テーブル・番号 | テーブル番号 |
| 経過時間 | 注文からの分数。ソート可能 |
| コース | コース名。設定で非表示可能 |
| メニュー | 商品名、印字名、商品メモ |
| トッピング | トッピング名と注文数量を掛けた個数。設定で非表示可能 |

| 状態 | 調理済にする、キャンセル、キャンセル済、配膳済、調理済 |

- 通常固定データでは30商品行を表示する。

- 猶予中の`キャンセル`で取消し、時間経過後は行を非表示にする。既定は3秒。
- `手動追加`はデータを追加せず、比較ラボでレビュー注文を追加できる旨をトースト表示する。

## 9. 調理済み画面

### 9.1 データと初期表示

- `#completed`で開く新UI向け履歴画面。

### 9.2 表示単位

| テーブル単位 | テーブルカード内を注文ごとに区切り、最終更新と注文件数を表示 |

検索とソートの結果に対して括り方だけを切り替え、件数要約を`N商品`、`N注文・N商品`、`Nテーブル・N商品`で表示する。

- 完了日時・新しい順
- 完了日時・古い順
- 注文日時・新しい順
- 注文日時・古い順
- テーブル番号順（数値を考慮）

### 9.5 未調理へ戻す

- `調理済み`商品だけ`未調理に戻す`を操作できる。
