# Kitchen Monitor UIモック比較と検証提案

- 比較日: 2026-07-27
- 当方モック: [Kitchen Monitor UI Prototypes](https://sm-hayashida.github.io/kitchen-monitor-ui-prototypes/)
- 比較対象: [佐々木さんのKitchen Monitorモック](https://yuukasasaki.github.io/KitchenMonitor/)
- 佐々木さん側の確認リビジョン: `abc90af55b9061a5e475e56b7bddd686b35bf272`
- 目的: どちらかをそのまま採用するのではなく、各モックが確認しようとしている機能・数値・操作を揃え、現場レビューでUI方針を決められる状態にする

## 1. 位置付け

| 観点 | 佐々木さんのモック | 当方のVueモック |
| --- | --- | --- |
| 主な役割 | 表示密度、完了後の状態変化、ページャー位置などを一画面で切り替えて試す | 注文別・テーブル別の実操作を保ったまま、比較パネルで密度・情報・時間・シナリオを切り替えて試す |
| 公開構成 | GitHub Pages。確認時点の公開リポジトリの`main`には、実行コードとアセットを内包した約7.7MBの`index.html`が1ファイルある | GitHub Pages。Vue/ViteのソースをGitHub Actionsでビルドし、生成した`dist`を公開する |
| ソース確認 | [GitHubリポジトリ](https://github.com/yuukasasaki/KitchenMonitor)で確認可能。ただし1ファイルにバンドルされており、変更差分は追いにくい | ページ、コンポーネント、状態管理、固定データ、仕様書を分けて確認可能 |
| データ・通信 | 固定シナリオ。API、認証、リアルタイム通信なし | 固定シナリオ。API、認証、リアルタイム通信なし |
| 本番仕様との関係 | UI検討用。本番の業務ルールや連携可否を証明しない | UI検討用。本番の業務ルールや連携可否を証明しない |

佐々木さん側の正確なGitHub Pages設定は公開リポジトリからは確認できないため、`main`直下を直接配信しているか、別のPages設定を使っているかは未確認である。

## 2. 機能比較

| 論点 | 佐々木さんのモック | 当方のVueモック | UIレビューで確認すること |
| --- | --- | --- | --- |
| 表示単位 | 注文、テーブル、設定 | 注文、テーブル、設定 | 調理担当が最初に必要とする単位。店舗・端末ごとの初期値 |
| レイアウト | 標準・高密度、3列・4列、ページャー下・左右 | 注文はN型横スクロール・N型ページ・Z型縦展開。テーブルはN型横スクロール・N型ページ | 一覧性と読みやすさ。長い注文を追うときの視線・スワイプ回数 |
| 注文の完了 | 完了開始から非表示まで複数段階の見た目を確認できる | 注文全体を完了し、3秒以内なら取消。経過後にカードを非表示 | 完了したことが伝わる時間、誤操作の戻しやすさ、画面から消えるタイミング |
| 商品の完了 | 数量パターンを切り替えて見た目を確認できる | 数量を1個単位で変更。テーブル別では全数完了後5秒で商品行を非表示し、猶予中は取消可能 | 部分調理の意味、数量の押しやすさ、商品行を残すか消すか |
| 商品詳細 | 主にカード上の情報量と状態表示を比較 | オプション、メモ、注文情報、時間情報、数量変更をポップオーバーで確認 | 一覧へ常時出す情報と、詳細へ隠す情報 |
| 同一商品集計 | 数量表示パターンの比較が中心 | コースIDとメニューID単位で未調理数を横断集計し、注文内訳を表示 | どの条件を「同じ商品」とみなすか。部門外の商品を合計へ含めるか |
| 時間警告 | 完了時間や非表示時間を操作パネルで比較。遅延設定の表示はあるが、一覧への反映は確認できない | 注文から15分を目標とし、残り3分以内を警告、超過後を赤で表示 | 時間の起点、店舗・商品・部門のどこで目標を持つか、期限到達時の表現 |
| 部門 | 部門設定のUIがある。現行一覧への実データ絞り込みは確認できない | 複数部門を選択し、該当商品と注文カードを絞り込める | 0件選択、初期選択、部門マスタとの対応、保存単位 |
| テーブル整理 | テーブル表示でカード状態を確認 | 複数注文の集約、並び替え、ピン留め、手動移動、グループ化 | デシャップで本当に必要な整理方法。保存と他端末同期 |
| 設定保存 | 数量表示パターンをブラウザへ保存 | 音量ON/OFFのみブラウザへ保存。比較値はURLで再現し、業務設定として保存しない | 店舗、端末、ユーザーのどこに保存するか |
| 同期・障害 | 未対応 | 未対応 | 他端末同期、競合、再接続、オフライン、エラー表示は別の設計・検証が必要 |

## 4. 次に揃えて試す値

次の値は業務仕様の決定値ではなく、UI比較の候補である。比較パネルで切り替えられる値は、Production Kitchen Monitorの設定項目や保存仕様を決めたものではない。

| 優先 | 論点 | 比較候補 | 見ること |
| --- | --- | --- | --- |
| 1 | 一覧の移動 | N型横スクロール、N型ページ、Z型縦展開、ページャー下・左右 | 対象注文を見つける時間、スワイプ・タップ数、現在位置の理解 |
| 1 | 完了から非表示まで | 0秒、3秒、5秒、8秒 | 完了の認知、誤操作取消の成功、消えるのが早い・遅いという感覚 |
| 1 | カード密度 | 最小幅290px、320px、360px相当 | 一画面の注文件数と、商品名・メモ・数量の読みやすさ |
| 1 | 長い注文 | 短い注文、標準、1列に収まらない注文 | カード分割位置、注文ヘッダーを繰り返さない場合の理解 |
| 2 | 数量 | 1個、2個、5個、10個と部分調理状態 | 数量の誤読・誤タップ、未調理数と調理済み数の区別 |
| 2 | 時間警告 | 目標15分、事前警告3分・5分 | 通常・期限間近・到達・超過の違いが一目で分かるか |
| 2 | 部門 | 全部門、1部門、複数部門、対象0件 | 絞り込み中であること、0件時、担当切替の速さ |
| 2 | テーブル整理 | 最古順、卓番号順、最終追加順、手動順、ピン、グループ | 日常運用で使うものと、設定を増やすだけのものを分ける |

## 5. レビューの進め方

1. 同じiPad横画面、同じ注文シナリオ、同じ担当者タスクで比較する。
2. 「好み」だけでなく、対象を見つける秒数、操作回数、誤操作、取消成功、迷った箇所を記録する。
3. レイアウト、完了・非表示、時間警告、保存・同期の順に決める。
4. 決まった業務ルールは要件文書へ、実際に触れるモック挙動は[現行モック機能仕様](./current-mock-functional-spec.md)へ反映する。
